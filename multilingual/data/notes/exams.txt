EXAMS cleaning / processing summary

Dataset:
- Source: mhardalov/exams.
- Config used: multilingual.
- Goal: add multilingual school/secondary exam-style MCQ data, especially Italian and Spanish, aligned with INCLUDE-like education/exam domains.

Available configs:
- Dataset has variants such as:
  - multilingual
  - multilingual_with_para
  - crosslingual_<languagecode>
  - crosslingual_with_para_<languagecode>
- We used multilingual, not multilingual_with_para, because support paragraphs were not needed and could add noise/length.

Splits:
- The multilingual config has:
  - train
  - validation
  - test
- We discussed whether to use the test split because it is larger.
- Decision for now: do not use the official test split.
- Reason: EXAMS is incorporated into INCLUDE-style benchmark construction, and our hidden evaluation may be INCLUDE-like. Using EXAMS test for training or model selection could increase leakage/contamination risk.
- Current policy:
  - train -> SFT train
  - validation -> SFT val
  - test -> unused for now
- If EdStem explicitly says public test splits may be used for training, this can be reconsidered, but it should be logged clearly.

Flattened format:
- split: original split name.
- id: example id.
- language: from info.language.
- subject: from info.subject.
- grade: from info.grade.
- stem: question text from question.stem.
- labels: list from question.choices.label.
- texts: list from question.choices.text.
- paras: list from question.choices.para.
- answerKey: correct answer label.
- n_choices: number of answer choices.

Target languages:
- We filtered to:
  - Italian
  - Spanish
- We decided not to include Bulgarian for now, even though it is large and Cyrillic, because it is not a target language and could dilute the multilingual SFT mix.

Target-language counts before cleaning:
- Italian: 1256 rows.
- Spanish: 235 rows.
- Total Italian/Spanish rows: 1491.

Answer distribution:
- answerKey values across Italian/Spanish:
  - B: 410
  - C: 396
  - A: 386
  - D: 298
  - E: 1
- The single E row is acceptable as long as E is present in labels.

Support paragraphs:
- Rows with non-empty support paragraph: 0.
- Therefore, the selected multilingual config effectively does not use support paragraphs for the Italian/Spanish rows.
- We did not need to include para in the prompt.

Corruption / validity checks:
- Rows with encoding corruption: 0.
- Rows where answerKey not in labels: 0.

Cleaning rules:
- Keep rows where:
  - split is train or validation.
  - language is Italian or Spanish.
  - stem is non-empty.
  - labels and texts are lists.
  - len(labels) == len(texts).
  - 2 <= len(labels) <= 5.
  - answerKey is in labels.
  - all option texts are non-empty.
  - no corruption characters are present.
- We accept variable numbers of choices, not only 4-choice MCQ.

Correct answer:
- For EXAMS, the correct answer is answerKey.
- answerKey is already the label, e.g. A/B/C/D/E.
- Unlike HEAD-QA, no remapping by aid position is needed.
- Loader should use row["answerKey"].strip().upper().

Prompt format:
- Use:
  <stem>

  A) <text for A>
  B) <text for B>
  C) <text for C>
  D) <text for D>
  E) <text for E, if present>
- The prompt should be dynamically formatted from labels/texts because the number of choices can vary.

Processed files:
- Saved under:
  multilingual/data/processed/exams/
- Main files should include:
  - exams_clean_all.csv
  - exams_rejected_all.csv
- Optional language-specific files can be saved for inspection.

Loader behavior:
- Read exams_clean_all.csv.
- Filter by language: italian or spanish.
- Use official split mapping:
  - train -> train
  - validation -> val
- Ignore test for now.
- Parse labels/texts if stored as strings in CSV.
- Format dynamic options from labels/texts.
- Set answer = answerKey.
- task_type = "mcq".
- Metadata should include original id, subject, grade, original split, and n_choices.

Suggested caps later:
- Italian EXAMS: keep or moderately cap; it has 1256 useful rows across many subjects.
- Spanish EXAMS: keep all, because only 235 rows.
- Do not cap in the cleaning notebook; cap later in the SFT builder.
