# Mystery Machine - Math Reasoning Data

Training and evaluation data for the math expert of the CS-552 (Spring 2026) Mystery Machine team's Qwen3-1.7B post-training project. This dataset bundles every data artifact used to produce and evaluate the shipped math model: the raw RL problem pool, the two learnability-filtered training sets corresponding to the two RL phases we ran, the supervised fine-tuning corpus (including chain-of-thought traces we distilled ourselves from a larger teacher), and the calibrated multi-source evaluation benchmark used for checkpoint selection and reporting.

## Repository structure

```text
math/
├── deepscaler_full.jsonl       # 40,309 raw RL problems (input to both filter phases)
├── benchmarks/
│   ├── broad.jsonl             # ~290 problems (MATH-500 + AIME 24/25 + GSM8K)
│   └── full.jsonl              # ~400 problems (broad + OlympiadBench + Minerva-MATH)
├── sft/
│   ├── sft_full.jsonl          # ~30K mixed-source chain-of-thought corpus
│   └── r1_distilled.jsonl      # ~400 AIME/AMC traces distilled by us from R1-Distill-32B
├── rl_phase1/
│   └── deepscaler_filtered.jsonl   # 1,219 problems in [1, 6]/8 vs base Qwen3-1.7B
└── rl_phase2/
    └── deepscaler_filtered.jsonl   # 1,235 problems in [1, 6]/8 vs shipped checkpoint
```

## Provenance and how each file was used

### `deepscaler_full.jsonl` - raw RL pool

A normalised version of `agentica-org/DeepScaleR-Preview-Dataset`: AIME 1984-2023, AMC pre-2023, Omni-MATH and Still, already deduplicated upstream against AIME 2024/2025 and MATH-500. We reformat each row into a single conversational schema so that downstream RL trainers can consume it without further preprocessing. This file is the upstream input to both RL filter phases below.

### `benchmarks/broad.jsonl` and `benchmarks/full.jsonl`

Two materialised profiles of our calibrated math evaluation suite. Each profile is a weighted mixture of public math benchmarks where the per-subset weight reflects the discriminative power of that subset against the classroom CI grader. Subsets are stratified MATH-500 (levels 1-5, 100 problems), MATH-500-hard (level 5 only, 80 problems), AIME 2024 (30 problems), AIME 2025 (30 problems), and a small GSM8K sample (50 problems, used as a catastrophic-forgetting tripwire). The `full` profile additionally includes OlympiadBench-Math (60 problems) and Hendrycks-MATH levels 4-5 (50 problems). Both profiles can be scored at the 4K nightly-CI contract (pass@1) and the 16K final-grading contract (pass@8) without modification.

### `sft/sft_full.jsonl`

The final ~30K-example training corpus for our supervised fine-tuning stage. Each row is a chat-format `messages` object `[system, user, assistant]` where the assistant turn carries a chain-of-thought reasoning trace wrapped in `<think>...</think>` followed by a single `\boxed{}` answer. Upstream sources are sampled and length-filtered (1500-8000 Qwen3 tokens) and globally deduplicated by a normalised problem fingerprint. Source attribution:

| Source | Count | Notes |
|---|---:|---|
| open-r1/OpenR1-Math-220k | 9,000 | R1-distilled traces |
| AI-MO/NuminaMath-CoT | 3,418 | Step-by-step solutions, wrapped synthetically |
| GAIR/LIMO | 557 | Hand-curated R1 traces |
| simplescaling/s1K-1.1 | 388 | Gemini-Thinking traces |
| nvidia/OpenMathReasoning | 16,000 | R1-style CoT subset |
| (this dataset) `r1_distilled.jsonl` | 400 | AIME/AMC traces distilled by us |

### `sft/r1_distilled.jsonl`

~400 chain-of-thought traces for AIME 2024, AIME 2025 and AMC 2023 problems, generated by sampling DeepSeek-R1-Distill-Qwen-32B (AWQ 4-bit quantised so it fits on a single A100) and rejection-sampling against Math-Verify on the gold answer. Up to four kept traces per problem. These rows are also included as the `distilled:aime_amc` source of `sft/sft_full.jsonl`; we ship them separately here so the distilled subset is independently downloadable.

### `rl_phase1/deepscaler_filtered.jsonl`

1,219 problems retained from `deepscaler_full.jsonl` after the first learnability-filtering pass. The filter procedure: for each problem, 8 vLLM rollouts of base Qwen3-1.7B at 4K context (T=0.7, top_p=0.95, top_k=20), scored via Math-Verify on the extracted `\boxed{}` answer; keep iff the base pass-count lies in [1, 6] of 8. The team system prompt is prepended to every row so that the training-time distribution matches the inference-time chat template. This is the RL training pool used for our first RL phase (the original GRPO+CISPO model that placed first on the classroom CI at 55%, and the subsequent GSPO model that scored 54%).

### `rl_phase2/deepscaler_filtered.jsonl`

1,235 problems retained from the same `deepscaler_full.jsonl` source, but the rollouts used to compute the filter come from our phase-1 GSPO checkpoint rather than from base Qwen3-1.7B. Identical band ([1, 6] of 8) and identical system-prompt prepending. The motivation is straightforward: after ~500 GSPO steps the policy has drifted; problems that were "learnable" against base may now be solved on every rollout (or never) and contribute zero gradient to the group-relative advantage. Re-filtering against the current policy state restores the variance signal that the GRPO/GSPO objective needs. This is the RL training pool for our phase-2 continuation run.

## Row schemas

### RL files (`deepscaler_full.jsonl`, `rl_phase*/deepscaler_filtered.jsonl`)

```json
{
  "messages": [
    {"role": "system", "content": "<team system prompt>"},
    {"role": "user",   "content": "<problem text>"}
  ],
  "solution": "<gold answer, Math-Verify compatible>",
  "source":   "agentica-org/DeepScaleR-Preview-Dataset",
  "n_pass":   3,
  "n_sampled": 8
}
```

`n_pass` and `n_sampled` are only present on the filtered files and record the rollout outcome that placed each problem in the learnability band.

### SFT files (`sft/sft_full.jsonl`, `sft/r1_distilled.jsonl`)

```json
{
  "messages": [
    {"role": "system",    "content": "<team system prompt>"},
    {"role": "user",      "content": "<problem>"},
    {"role": "assistant", "content": "<think>...</think>\n\n\\boxed{<answer>}"}
  ],
  "source": "open-r1/OpenR1-Math-220k"
}
```

### Benchmark files (`benchmarks/broad.jsonl`, `benchmarks/full.jsonl`)

```json
{
  "id":     "math500_hard:00",
  "prompt": "<problem text>",
  "answer": "<gold answer>",
  "subset": "math500_hard",
  "weight": 1.0,
  "source": "<upstream provenance string>"
}
```

The `subset` and `weight` fields let downstream scorers compute the weighted aggregate metric directly.

## Minimal loading recipe

```python
from datasets import load_dataset

REPO = "cs-552-2026-mystery-machine/math"

eval_broad = load_dataset(REPO, data_files="benchmarks/broad.jsonl",  split="train")
eval_full  = load_dataset(REPO, data_files="benchmarks/full.jsonl",   split="train")
sft_full   = load_dataset(REPO, data_files="sft/sft_full.jsonl",      split="train")
r1_distill = load_dataset(REPO, data_files="sft/r1_distilled.jsonl",  split="train")
rl_phase1  = load_dataset(REPO, data_files="rl_phase1/deepscaler_filtered.jsonl", split="train")
rl_phase2  = load_dataset(REPO, data_files="rl_phase2/deepscaler_filtered.jsonl", split="train")
```
